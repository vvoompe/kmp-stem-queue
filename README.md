# Імітаційна й аналітична модель пункту видачі інтернет-замовлень

Дисципліна «Комп'ютерне моделювання процесів», тема № 10. Мета моделі —
оцінити, як кількість працівників впливає на обслуговування клієнтів, втрати
через заповнення системи й простій персоналу.

## Модель і параметри

- Робочий день: 10 годин (600 хвилин), 40 кроків по 15 хвилин.
- Потік клієнтів за крок: розподіл Пуассона із середнім `lam`.
- Кількість товарів: геометричний розподіл з `P_ITEMS = 0.3`.
- Час обслуговування: `0.5 × кількість товарів + 2` хвилини; з імовірністю
  `0.1` додаються 3 хвилини на оформлення відмови.
- `C` — кількість працівників; `queue_limit` (m) — місць очікування. Повна
  місткість системи становить `C + m` клієнтів, включно з тими, кого вже
  обслуговують.
- Теоретичний середній час обслуговування `E[S] = 0.5 / 0.3 + 2 + 0.1 × 3
  = 3.9667 хв`; середня інтенсивність обслуговування одного працівника
  `μ = 1 / E[S]`.

## Запуск

З кореня проєкту встановіть залежності та запускайте модулі:

```powershell
pip install -r requirements.txt
python -m src.analytics
python -m src.stage3_analytic
python -m src.plots
```

`analytics.py` робить 100 прогонів на кожне значення `C` (за замовчуванням
від 1 до 4) і виводить середні обслужених/втрачених клієнтів, простій, чергу
та час очікування. Фіксоване початкове значення генератора `seed=42` дає
відтворювані результати. Його можна змінити через функцію
`run_analytics(queue_limit, lam, workers=range(1, 5), runs=100, seed=42)`.

`plots.py` зберігає графіки у папку `plots/`:

- гістограма кількості товарів у замовленні;
- гістограма часу обслуговування;
- стовпчикова діаграма середньої кількості втрачених клієнтів залежно від C;
- графік кількості клієнтів у черзі за часом одного дня.

Усі графіки двовимірні, мають заголовок, легенду й одиниці вимірювання на
осях. Під час оформлення звіту підпис («Рисунок N - ...») додається окремим
абзацом під зображенням, а не всередині нього.

## Аналітична модель і обмеження

`stage3_analytic.py` використовує скінченну марковську модель M/M/C/(C+m):
`λ = lam / 15` клієнтів за хвилину; `μ = 1/E[S]`; `K = C + m`.
У стані `n` системи зайнято `min(n, C)` працівників. Стаціонарні ймовірності
обчислюються рекурентно:

```text
q0 = 1 / Σ(w0..wK),  w0 = 1
wn = w(n-1) × λ / (min(n, C) × μ),  n = 1..K
qn = wn / Σ(w0..wK)
```

З них отримуються ймовірність відмови `Pвідм = qK`, пропускна здатність
`A = λ × (1 - qK)`, середня черга
`Lq = Σ(max(n-C, 0) × qn)`, час очікування `Wq = Lq / A` (закон Літтла),
а середня частка простою працівників
`Σ((C-n) × qn, n=0..C-1) / C`.
Добові кількості обслугованих і втрачених клієнтів — це відповідні
інтенсивності, помножені на 600 хвилин.

Зауваження до порівняння: реальна імітація має пуассонівські пакетні
надходження раз на 15 хвилин і неекспоненційний час обслуговування.
Аналітичні формули M/M/C/(C+m) припускають неперервний пуассонівський потік
та експоненційний час обслуговування із тією самою середньою величиною.
Тому розбіжність очікувана: вона є наслідком наближення та випадкової
похибки скінченної кількості прогонів, а не тотожності двох моделей.

`compare_with_simulation(queue_limit, lam, workers, runs, seed)` повертає
спільну таблицю середніх значень імітації та аналітичних оцінок для однакових
параметрів. «Простій» у цій таблиці — частка оплачуваного часу працівників,
коли працівник не обслуговує клієнта; окремо зберігається частка кроків, коли
вся система була без роботи.
